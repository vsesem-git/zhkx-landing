# 🏠 ЖКУ · Крым — личная система автоматического учёта коммунальных услуг

Веб-приложение (HTML5 + CSS3 + JavaScript, **без сборки и без внешних зависимостей**) для учёта
начислений и авансов по **6 объектам недвижимости** в Крыму: г. Алушта (кв. 31, 115, 3, 102, 108)
и с. Перевальное (дом «Учительская 45»). Рядом — небольшой сервер на Node.js, который **хранит все
данные в `.js`-файле** `data/state.js` и раздаёт само приложение.

Вся нормативная информация — реестр объектов, площади, тарифные сетки, параметры счётчиков и даты
госповерки — **жёстко зашита в data-слой** `assets/js/data/config.js` (сервер исполняет этот же файл
в песочнице `vm`, поэтому справочники и расчёты не расходятся). Браузер держит локальную копию
состояния в `localStorage` и работает офлайн: изменения копятся в очереди операций и уходят на сервер,
как только связь появится. Дополнительно есть JSON-бэкап, CSV и история ревизий.

```bash
# 1. Сервер + приложение (рекомендуется) — данные в data/state.js
npm start                      # → http://localhost:8000  (токен печатается в консоль)
npm run dev                    # то же, но с демо-токеном «demo-token» (песочница)
npm run seed -- --demo         # наполнить сервер демо-историей за 12 месяцев

# 2. Только интерфейс (как раньше: всё в localStorage, без сервера)
python3 -m http.server 8000 --bind 0.0.0.0     # приложение работает и простым открытием index.html

# 3. Проверки
npm run test          # 182 автотеста расчётного движка и состояния (без зависимостей)
npm run test:dom      # 89 DOM-тестов интерфейса (нужен jsdom)
npm run test:server   # 126 тестов сервера и сквозного сценария синхронизации
npm run test:all      # всё вместе
```

Готовые архивы для развёртывания — в разделе **Releases** репозитория
(`zhkx-demo-static.zip` — демо без сервера, `zhkx-server.zip` — полный комплект),
собираются командой `npm run build:demo`. Подробно — «Развёртывание на своём сервере» ниже.

Полезные команды сервера: `npm run status` (ревизия, размер, история), `npm run token`
(показать токен), `npm run revisions` (список ревизий), `npm run backup` (копия JSON),
`npm run validate` (проверка data-слоя), `npm run reminders` (что уйдёт в Telegram).

## ⚡ Тарифные сетки электроэнергии

Расход = **текущее показание − предыдущее**. Ступени **кумулятивные** (прогрессивная шкала):
каждый следующий диапазон оплачивается по своей ставке, предыдущие — по своим.

### «Город + плита» — объекты № 1, 2 (одноставочный учёт)

| Объём за месяц | Ставка |
|---|---|
| до 250 кВтч включительно | 4,33 ₽/кВтч |
| от 250 до 800 кВтч | первые 250 кВтч — 4,33 ₽; остаток — 5,45 ₽ |
| свыше 800 кВтч | первые 250 — 4,33 ₽; следующие 550 — 5,45 ₽; остаток — 9,20 ₽ |

Пример: 900 кВтч = 250 × 4,33 + 550 × 5,45 + 100 × 9,20 = **5 000,00 ₽**

### «Негазифицирован + город» — объекты № 3, 4, 5

## 💧 Водоснабжение — ГУП РК «Вода Крыма»

Начисление = (текущее − предыдущее показание) × тариф:

| Вариант | Ставка | Примечание |
|---|---|---|
| Архивный личный тариф | 37,02 ₽/м³ | исторический тариф владельца |
| **Актуальный тариф** | **47,96 ₽/м³** | применяется по умолчанию |
| Индексируемый тариф | 54,67 ₽/м³ | переключаемый вариант |

**Селектор периодов.** Тариф задаётся не «вообще», а на конкретный месяц: график
(`WATER_TARIFF_SCHEDULE_DEFAULT` в data-слое + правки в интерфейсе) определяет, какая ставка
действует с указанного периода и до следующей строки. Пример графика:

| Период действия | Тариф | Ставка |
|---|---|---|
| до янв. 2026 | Актуальный | 47,96 ₽/м³ |
| янв. 2026 — июн. 2026 | Архивный | 37,02 ₽/м³ |
| с июл. 2026 | Актуальный | 47,96 ₽/м³ |
| с янв. 2027 | Индексируемый | 54,67 ₽/м³ |

Строки графика добавляются в разделе **«Тарифы» → «Селектор периодов»** (с кнопкой «Применить график
ко всем объектам»), а расчёт при внесении показаний за прошлый месяц автоматически берёт ставку,
действовавшую **в том месяце**. В калькуляторе можно дополнительно переопределить тариф для одной
конкретной записи — постоянный тариф объекта при этом не меняется.

**Исторические архивы водомеров.** В data-слой занесены реальные показания по трём квартирам
(раздел «Водомеры»): кв. 115 — 19 записей, кв. 3 — 15 записей, кв. 102 — 26 записей (295 → 550 м³).
Архив используется:

* для расчёта **среднего расхода воды** (последние 3 записи) — например, по кв. 102 это 11 м³/мес →
  ≈ 527,56 ₽/мес по текущему тарифу, — пока в журнале начислений ещё мало данных;
* для **переноса истории в журнал** одной кнопкой: сумма каждого месяца считается по тарифу,
  действовавшему в этом месяце, а месяцы без расхода («0 м³») можно включать или пропускать;
* для выгрузки архива в CSV и контроля показаний (система подсвечивает записи, где показание
  меньше предыдущего).

## 🛠️ Возможности

1. **Калькулятор «на лету».** Выбор услуги «Содержание МКД» / «Капитальный ремонт» мгновенно
   умножает площадь объекта на его тариф и заполняет поле «Начислено». Для электроэнергии расход
   раскрывается по ступеням (объём × ставка = сумма), для воды — по тарифу, интернет — фиксированная
   плата за N месяцев. Все поля открыты для ручной правки: при вводе своей суммы авторежим
   отключается и появляется пометка «сумма изменена вручную».
2. **Депозитный кошелёк (авансы).** Для каждого объекта и услуги можно внести крупный аванс
   (например, 5 000 ₽ на капремонт). Сумма хранится в `localStorage`; при добавлении ежемесячного
   начисления аванс **автоматически уменьшается** (движение «Начисление» со знаком «минус»), а в
   журнале видно, какая часть начисления покрыта авансом, а какая ушла в задолженность.
3. **Прогноз времени.** Остаток аванса делится на расчётный ежемесячный платёж:
   для кв. 102 по капремонту 52,60 м² × 11,46 ₽ = **602,80 ₽/мес**, поэтому
   «Аванса 5 000,00 ₽ хватит на **8.3 мес.** (ориентировочно до **июня 2027 года**)».
   Для счётчиков прогноз строится на **среднем расходе за последние 3 месяца** из журнала.
4. **Мониторинг госповерки.** Дата следующей поверки = дата последней поверки + межповерочный
   интервал; далее сравнение с датой компьютера: `❌ ПОВЕРКА ИСТЕКЛА`, `⚠️ ТРЕБУЕТСЯ ПОВЕРКА`
   (менее 30 дней), `✅ Поверка ОК`. Плюс шкала износа срока и сводка оповещений на дашборде.
5. **Аналитика и резервные копии.** Круговая диаграмма Chart.js (структура расходов по объектам
   или по услугам — переключается фильтром), динамика начислений по месяцам (6/12/24), таблицы
   истории с фильтрами и живым поиском, экспорт/импорт JSON-бэкапа, выгрузка журнала в CSV для Excel.
6. **Распределение начисления по секциям** (необязательно): 1-й и 2-й этажи по площади, доли
   собственников в процентах, жильцы по количеству (3 человека → 5 400 ₽) или фиксированные суммы.
7. **Сервер и синхронизация.** Данные живут на сервере в `.js`-файле `data/state.js` (история — до
   60 ревизий), браузер держит локальную копию и очередь операций: приложение работает офлайн, а
   изменения уходят сами, когда появляется связь. В шапке — индикатор состояния, в разделе «Данные» —
   ревизия, контрольная сумма, история с откатом, вход по токену и напоминания в Telegram.
   Приложение устанавливается на телефон (PWA) и открывается без интернета.
8. **Раздел «Водомеры»** — история показаний по каждому объекту, средний расход за 3 месяца, перенос
   архива в журнал (обычный / включая месяцы без расхода / пересчёт по текущему графику тарифов),
   экспорт CSV. Лицевые счета Вода Крыма заполнены для кв. 115, 3, 102, 108; по объектам № 1 и № 6
   отображается статус «данные уточняются», туда же подставляются средние расходы для прогнозов.

Порядок подключения скриптов задан в `index.html`: `data → core → ui`. Data-слой заморожен
(`Object.freeze`), поэтому расчёты невозможно случайно испортить правкой в рантайме; все
пользовательские изменения хранятся отдельно в состоянии как «правки» (overrides).

### Модель учёта денег

Единый реестр движений по паре «объект + услуга»:

| Тип | Знак | Смысл |
|---|---|---|
| `opening` | ± | перенос сальдо на начало учёта |
| `deposit` | + | внесённый аванс |
| `payment` | + | оплата начисления по квитанции |
| `correction` | ± | ручная корректировка |
| `charge` | − | начисление за месяц (создаётся записью журнала) |

`баланс = Σ движений`: положительный — остаток авансового кошелька, отрицательный — задолженность.
Хронологический проход определяет, сколько каждого начисления закрыто авансом.

Записи журнала помечаются происхождением (`origin`): `user` — внесены вручную, `archive` — перенесены
из исторического архива водомера, `demo` — демонстрационные. Это позволяет при первом запуске
подмешать реальную историю воды вместо выдуманной, а в разделе «Данные» видеть, что именно введено
пользователем.

## ☁️ Сервер: хранение данных в .js-файлах и синхронизация

```
server/index.js         HTTP-сервер: статика приложения + REST API (порт 8000)
server/api.js           REST: health, login, state, events, config, reminders, revisions, restore, export, import, reset
server/store.js         хранилище data/state.js: разбор без eval, атомарная запись, история ревизий, применение операций
server/config-loader.js исполняет data-слой (config.js) в песочнице vm → справочники для API и напоминаний
server/auth.js          доступ по токену (ZHKX_TOKEN | демо-режим | data/auth.json, режим 600), защита от перебора
server/notify.js        напоминания: показания 20–25 числа, поверки, долги; отправка в Telegram
server/cli.js           командная строка: status/token/rotate-token/revisions/restore/backup/reminders/send/validate
data/state.js           СОСТОЯНИЕ: window.ZHKX.StateData = { … }  (создаётся автоматически, в git не хранится)
data/history/           до 60 последних ревизий state-NNNNN-ГГГГММДД-ЧЧММСС.js
data/auth.json          токен доступа (создаётся при первом запуске, права 600)
```

**Как хранятся данные.** `data/state.js` — обычный исполняемый js-файл с заголовком-комментарием
(ревизия, время, контрольная сумма sha256) и объектом состояния:

```js
window.ZHKX = window.ZHKX || {};
window.ZHKX.StateData = { meta: { revision: 42 }, settings: {…}, objects: {…},
                          movements: […], journal: […], meterSnapshots: {…}, tombstones: {…} };
```

Сервер разбирает его **без `eval`** (сканирование по балансу скобок), при каждой записи увеличивает
ревизию, кладёт предыдущую версию в `data/history/` и делает атомарную замену через временный файл.
Скачать текущий файл можно по `GET /data/state.js?token=…`, посмотреть историю — в приложении
(раздел «Данные» → «Сервер и синхронизация» → история ревизий → «Откатить»).

**Как работает синхронизация.** Каждое действие пользователя (начисление, аванс, правка тарифа,
показания) сразу применяется локально и превращается в операцию очереди:

| Операция | Когда создаётся |
|---|---|
| `upsert-entry` / `delete-entry` | запись журнала: добавление, правка, удаление |
| `upsert-movement` / `delete-movement` | движение кошелька (аванс, оплата, начисление) |
| `set-object` | правки объекта: площадь, тарифы услуг, прибор учёта, график тарифов воды |
| `set-settings` | настройки (тема, активный период, основной тариф воды) |
| `set-snapshot` | текущие показания счётчика |
| `replace-state` | импорт бэкапа, демо-данные, полный сброс |

Затем `assets/js/core/sync.js` отправляет пачку на `POST /api/events` с базовой ревизией. Сервер
применяет операции **идемпотентно** (повторная отправка после обрыва связи ничего не дублирует),
разрешает конфликты по времени изменения (last-write-wins) и помнит удаления («надгробия»), чтобы
удалённая запись не «воскресла» с другого устройства. Автосинхронизация срабатывает после каждого
изменения, раз в минуту, при появлении сети и при возврате на вкладку; статус виден в шапке
(бейдж) и подробно — в разделе «Данные».

**Безопасность.** API закрыт токеном: `ZHKX_TOKEN=…` (свой), `ZHKX_DEMO_AUTH=1` (песочница,
токен `demo-token` — приложение подключается к ней автоматически, без ввода) или автоматически
сгенерированный токен в `data/auth.json` (права 600).
Наружу отдаются только `index.html`, манифест, service worker и `assets/**`; каталоги `data/` и
`server/` недоступны (проверяется тестом, включая попытки обхода через `..`). Данные личные
(ФИО, адреса, лицевые счета), поэтому не выкладывайте `data/` в публичный доступ.

**Напоминания в Telegram.** Задайте `ZHKX_TELEGRAM_TOKEN` и `ZHKX_TELEGRAM_CHAT` — сервер раз в час
проверит: не переданы ли показания (20–25 числа), не истекает ли госповерка (≤30 дней / ≤7 дней),
не кончается ли аванс (меньше 1,5 месяца) и нет ли задолженности. Список и кнопка «Отправить сейчас» —
в окне синхронизации, предпросмотр — `npm run reminders`.

**Установка на телефон.** Приложение — PWA: `manifest.webmanifest` + `sw.js` кэшируют интерфейс,
поэтому оно открывается без интернета (данные — из локальной копии), а из браузера его можно
добавить на домашний экран.

## 💾 Данные и резервные копии

* Основное хранилище — **сервер**: `data/state.js` (+ история ревизий в `data/history/`).
  В браузере остаётся локальная копия (ключ `zhkx.crimea.state.v1` в `localStorage`) для офлайн-работы
  и очередь неотправленных операций.
* Раздел **«Данные»** → карточка «Сервер и синхронизация»: ревизия, контрольная сумма, размер файла,
  очередь, история ревизий с откатом, кнопка «Отправить локальное состояние целиком».
* Раздел **«Данные»** → кнопка «Скачать JSON-бэкап» (файл `zhkx-backup-ГГГГММДД-ЧЧММ.json`).
* Импорт поддерживает два режима: **заменить** (полное восстановление) и **слить** (добавить только
  отсутствующие периоды — удобно для переноса между устройствами).
* Очистка данных браузера удалит историю — выгружайте бэкап регулярно.
* При первом запуске система наполняет себя демонстрационной историей за 12 месяцев (включая
  крупные авансы), чтобы интерфейс был наглядным; очистить её можно в разделе «Данные».
  Для воды по кв. 115, 3 и 102 при этом используются **реальные архивы водомеров** из data-слоя,
  а не выдуманные значения.

## ✏️ Как менять тарифы и данные

Все нормативные значения правятся в одном месте — `assets/js/data/config.js`:

* `OBJECTS` — адреса, лицевые счета, площади, владельцы, тарифы услуг, приборы учёта и госповерка;
* `ELECTRICITY_TARIFFS` — ступени по категориям (`city_stove`, `ungasified_city`, `village`) и зонам;
* `WATER_TARIFFS` — тарифы ГУП РК «Вода Крыма»;
* `RULES` — порог предупреждения о поверке (30 дней), окно усреднения расхода (3 месяца).

После правки достаточно обновить страницу — либо поправить значения прямо в интерфейсе
(⚙️ в карточке объекта или услуги): такие правки сохраняются в `localStorage` и имеют приоритет
над реестром, при этом кнопка «Вернуть значения реестра» откатывает их.

## 🚀 Развёртывание на своём сервере

Приложению нужен только Node.js 18+ (внешних зависимостей нет — сервер написан на стандартной
библиотеке). Данные лежат в каталоге `data/`, который создаётся сам и в git не попадает.

### Вариант 1. Проверка за минуту

```bash
git clone https://github.com/vsesem-git/zhkx-landing.git && cd zhkx-landing
npm run dev                 # демо-режим: http://localhost:8000, вход без токена
npm run seed -- --demo      # (необязательно) демо-история на сервер
```

Для боевого запуска: `ZHKX_TOKEN=$(openssl rand -hex 24) npm start` — токен возьмите из вывода
или командой `npm run token`; введите его в приложении (окно «Сервер и синхронизация»).

### Вариант 2. Docker

```bash
git clone https://github.com/vsesem-git/zhkx-landing.git && cd zhkx-landing
docker build -f deploy/Dockerfile -t zhkx-crimea:2.0.0 .
docker run -d --name zhkx -p 8000:8000 \
  -v zhkx-data:/app/data \
  -e ZHKX_TOKEN=свой-секрет \
  --restart unless-stopped zhkx-crimea:2.0.0

# или всё то же одной командой:
ZHKX_TOKEN=свой-секрет docker compose -f deploy/docker-compose.yml up -d
```

Том `zhkx-data` хранит `state.js`, историю ревизий и `auth.json`; обновление —
`docker compose -f deploy/docker-compose.yml build && … up -d` (данные сохраняются).

### Вариант 3. systemd + nginx (как на своём сервере)

```bash
sudo useradd --system --home /opt/zhkx-landing zhkx
sudo git clone https://github.com/vsesem-git/zhkx-landing.git /opt/zhkx-landing
sudo install -d -o zhkx -g zhkx /var/lib/zhkx
sudo cp /opt/zhkx-landing/deploy/zhkx.service /etc/systemd/system/
sudo systemctl edit zhkx          # Environment=ZHKX_TOKEN=свой-секрет
sudo systemctl daemon-reload && sudo systemctl enable --now zhkx
```

`deploy/zhkx.service` слушает `127.0.0.1:8000` и пишет данные в `/var/lib/zhkx`.
`deploy/nginx.conf.example` — обратный прокси с HTTPS и basic-auth (лишним не будет: в приложении
адреса, ФИО и лицевые счета). Резервная копия данных — `npm run backup`
(или `tar czf backup.tgz -C /var/lib/zhkx .`).

### Демо-бандлы для публикации

```bash
npm run build:demo
```

Собирает в `dist/` два архива (без внешних зависимостей, с контрольными суммами):

| Архив | Что внутри | Куда подходит |
|---|---|---|
| `zhkx-demo-static.zip` (~116 КБ) | только интерфейс: `index.html`, `assets/`, манифест, service worker | любой статический хостинг, GitHub Pages, демонстрация без сервера: история — в localStorage браузера, при первом открытии подставляется демо-история |
| `zhkx-server.zip` (~200 КБ) | приложение + сервер + `tools/` + `deploy/` + README | свой сервер: `npm start`, Docker, systemd |

Статическая сборка проверена тестом: при отсутствии API-сервера приложение честно переходит
в локальный режим, ничего не ломается и не пишет ошибок в консоль.

> ⚠️ **О доступе.** В статической сборке справочник объектов (`assets/js/data/config.js`) открыт
> любому, кто откроет страницу: адреса, ФИО, лицевые счета. Для публичного демо включайте
> basic-auth (см. `deploy/nginx.conf.example`) или используйте серверную сборку с токеном.
> Архив данных `data/` в git и в релизы не попадает — он создаётся на вашем сервере.

## ⚠️ Что стоит уточнить

* **Лицевые счета водоснабжения объектов № 1 (кв. 31) и № 6 (дом)** помечены «данные уточняются» —
  как и указано в исходных данных. Впишите номер через ⚙️ «Параметры услуги» → «Лицевой счёт
  ГУП РК "Вода Крыма"».
* **Приборы учёта воды** (номера, модели, даты госповерки) пока не заполнены: в разделе «Госповерка»
  они отображаются как «Нет данных». Заполните через ⚙️ — система сразу начнёт следить за сроком.
* **Даты индексации тарифа воды** в исходных данных не указаны, поэтому базовый график состоит из
  одной строки (актуальный тариф 47,96 ₽ на все периоды). Добавьте строки в селекторе периодов,
  когда появятся даты изменений, — прошлые начисления при этом не изменятся.
* Тарифы обновляются региональными постановлениями: после очередной индексации поправьте ставки
  в `config.js` (или в интерфейсе) — история прошлых месяцев сохраняется.
