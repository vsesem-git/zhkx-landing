# 🏠 ЖКУ · Крым — личная система автоматического учёта коммунальных услуг

Автономное веб-приложение (HTML5 + CSS3 + JavaScript, **без сборки и без бэкенда**) для учёта
начислений и авансов по **6 объектам недвижимости** в Крыму: г. Алушта (кв. 31, 115, 3, 102, 108)
и с. Перевальное (дом «Учительская 45»).

Вся нормативная информация — реестр объектов, площади, тарифные сетки, параметры счётчиков и даты
госповерки — **жёстко зашита в data-слой** `assets/js/data/config.js`. Интерфейс работает полностью
в браузере, история хранится в `localStorage`, выгружается и восстанавливается JSON-бэкапом.

```bash
# Запуск (любой статический сервер; приложение работает и простым открытием index.html)
python3 -m http.server 8000 --bind 0.0.0.0     # → http://localhost:8000

# Проверки
node tools/selftest.mjs        # 116 автотестов расчётного движка (без зависимостей)
npm install --no-save jsdom && node tools/domtest.mjs   # 58 DOM-тестов интерфейса
```

## ⚡ Тарифные сетки электроэнергии

Расход = **текущее показание − предыдущее**. Ступени **кумулятивные** (прогрессивная шкала):
каждый следующий диапазон оплачивается по своей ставке, предыдущие — по своим.

### «Город + плита» — объекты № 1, 2 (одноставочный учёт)

| Объём за месяц | Ставка |
|---|---|
| до 250 кВтч включительно | 4,33 ₽/кВтч |
| от 250 до 800 кВтч | первые 250 кВтч — 4,33 ₽; остаток — 5,45 ₽ |
| свыше 800 кВтч | первые 250 — 4,33 ₽; следующие 550 — 5,45 ₽; остаток — 9,20 ₽ |

Пример: 900 кВтч = 250 × 4,33 + 550 × 5,45 + 100 × 9,20 = **5 000,00 ₽**

### «Негазифицирован + город» — объекты № 3, 4, 5

## 💧 Водоснабжение — ГУП РК «Вода Крыма»

Начисление = (текущее − предыдущее показание) × тариф:

| Вариант | Ставка | Примечание |
|---|---|---|
| Архивный личный тариф | 37,02 ₽/м³ | исторический тариф владельца |
| **Актуальный тариф** | **47,96 ₽/м³** | применяется по умолчанию |
| Индексируемый тариф | 54,67 ₽/м³ | переключаемый вариант |

**Селектор периодов.** Тариф задаётся не «вообще», а на конкретный месяц: график
(`WATER_TARIFF_SCHEDULE_DEFAULT` в data-слое + правки в интерфейсе) определяет, какая ставка
действует с указанного периода и до следующей строки. Пример графика:

| Период действия | Тариф | Ставка |
|---|---|---|
| до янв. 2026 | Актуальный | 47,96 ₽/м³ |
| янв. 2026 — июн. 2026 | Архивный | 37,02 ₽/м³ |
| с июл. 2026 | Актуальный | 47,96 ₽/м³ |
| с янв. 2027 | Индексируемый | 54,67 ₽/м³ |

Строки графика добавляются в разделе **«Тарифы» → «Селектор периодов»** (с кнопкой «Применить график
ко всем объектам»), а расчёт при внесении показаний за прошлый месяц автоматически берёт ставку,
действовавшую **в том месяце**. В калькуляторе можно дополнительно переопределить тариф для одной
конкретной записи — постоянный тариф объекта при этом не меняется.

**Исторические архивы водомеров.** В data-слой занесены реальные показания по трём квартирам
(раздел «Водомеры»): кв. 115 — 19 записей, кв. 3 — 15 записей, кв. 102 — 26 записей (295 → 550 м³).
Архив используется:

* для расчёта **среднего расхода воды** (последние 3 записи) — например, по кв. 102 это 11 м³/мес →
  ≈ 527,56 ₽/мес по текущему тарифу, — пока в журнале начислений ещё мало данных;
* для **переноса истории в журнал** одной кнопкой: сумма каждого месяца считается по тарифу,
  действовавшему в этом месяце, а месяцы без расхода («0 м³») можно включать или пропускать;
* для выгрузки архива в CSV и контроля показаний (система подсвечивает записи, где показание
  меньше предыдущего).

## 🛠️ Возможности

1. **Калькулятор «на лету».** Выбор услуги «Содержание МКД» / «Капитальный ремонт» мгновенно
   умножает площадь объекта на его тариф и заполняет поле «Начислено». Для электроэнергии расход
   раскрывается по ступеням (объём × ставка = сумма), для воды — по тарифу, интернет — фиксированная
   плата за N месяцев. Все поля открыты для ручной правки: при вводе своей суммы авторежим
   отключается и появляется пометка «сумма изменена вручную».
2. **Депозитный кошелёк (авансы).** Для каждого объекта и услуги можно внести крупный аванс
   (например, 5 000 ₽ на капремонт). Сумма хранится в `localStorage`; при добавлении ежемесячного
   начисления аванс **автоматически уменьшается** (движение «Начисление» со знаком «минус»), а в
   журнале видно, какая часть начисления покрыта авансом, а какая ушла в задолженность.
3. **Прогноз времени.** Остаток аванса делится на расчётный ежемесячный платёж:
   для кв. 102 по капремонту 52,60 м² × 11,46 ₽ = **602,80 ₽/мес**, поэтому
   «Аванса 5 000,00 ₽ хватит на **8.3 мес.** (ориентировочно до **июня 2027 года**)».
   Для счётчиков прогноз строится на **среднем расходе за последние 3 месяца** из журнала.
4. **Мониторинг госповерки.** Дата следующей поверки = дата последней поверки + межповерочный
   интервал; далее сравнение с датой компьютера: `❌ ПОВЕРКА ИСТЕКЛА`, `⚠️ ТРЕБУЕТСЯ ПОВЕРКА`
   (менее 30 дней), `✅ Поверка ОК`. Плюс шкала износа срока и сводка оповещений на дашборде.
5. **Аналитика и резервные копии.** Круговая диаграмма Chart.js (структура расходов по объектам
   или по услугам — переключается фильтром), динамика начислений по месяцам (6/12/24), таблицы
   истории с фильтрами и живым поиском, экспорт/импорт JSON-бэкапа, выгрузка журнала в CSV для Excel.
6. **Распределение начисления по секциям** (необязательно): 1-й и 2-й этажи по площади, доли
   собственников в процентах, жильцы по количеству (3 человека → 5 400 ₽) или фиксированные суммы.
7. **Раздел «Водомеры»** — история показаний по каждому объекту, средний расход за 3 месяца, перенос
   архива в журнал (обычный / включая месяцы без расхода / пересчёт по текущему графику тарифов),
   экспорт CSV. Лицевые счета Вода Крыма заполнены для кв. 115, 3, 102, 108; по объектам № 1 и № 6
   отображается статус «данные уточняются», туда же подставляются средние расходы для прогнозов.


Порядок подключения скриптов задан в `index.html`: `data → core → ui`. Data-слой заморожен
(`Object.freeze`), поэтому расчёты невозможно случайно испортить правкой в рантайме; все
пользовательские изменения хранятся отдельно в состоянии как «правки» (overrides).

### Модель учёта денег

Единый реестр движений по паре «объект + услуга»:

| Тип | Знак | Смысл |
|---|---|---|
| `opening` | ± | перенос сальдо на начало учёта |
| `deposit` | + | внесённый аванс |
| `payment` | + | оплата начисления по квитанции |
| `correction` | ± | ручная корректировка |
| `charge` | − | начисление за месяц (создаётся записью журнала) |

`баланс = Σ движений`: положительный — остаток авансового кошелька, отрицательный — задолженность.
Хронологический проход определяет, сколько каждого начисления закрыто авансом.

Записи журнала помечаются происхождением (`origin`): `user` — внесены вручную, `archive` — перенесены
из исторического архива водомера, `demo` — демонстрационные. Это позволяет при первом запуске
подмешать реальную историю воды вместо выдуманной, а в разделе «Данные» видеть, что именно введено
пользователем.

## 💾 Данные и резервные копии

* Всё хранится локально: ключ `zhkx.crimea.state.v1` в `localStorage` браузера.
* Раздел **«Данные»** → кнопка «Скачать JSON-бэкап» (файл `zhkx-backup-ГГГГММДД-ЧЧММ.json`).
* Импорт поддерживает два режима: **заменить** (полное восстановление) и **слить** (добавить только
  отсутствующие периоды — удобно для переноса между устройствами).
* Очистка данных браузера удалит историю — выгружайте бэкап регулярно.
* При первом запуске система наполняет себя демонстрационной историей за 12 месяцев (включая
  крупные авансы), чтобы интерфейс был наглядным; очистить её можно в разделе «Данные».
  Для воды по кв. 115, 3 и 102 при этом используются **реальные архивы водомеров** из data-слоя,
  а не выдуманные значения.

## ✏️ Как менять тарифы и данные

Все нормативные значения правятся в одном месте — `assets/js/data/config.js`:

* `OBJECTS` — адреса, лицевые счета, площади, владельцы, тарифы услуг, приборы учёта и госповерка;
* `ELECTRICITY_TARIFFS` — ступени по категориям (`city_stove`, `ungasified_city`, `village`) и зонам;
* `WATER_TARIFFS` — тарифы ГУП РК «Вода Крыма»;
* `RULES` — порог предупреждения о поверке (30 дней), окно усреднения расхода (3 месяца).

После правки достаточно обновить страницу — либо поправить значения прямо в интерфейсе
(⚙️ в карточке объекта или услуги): такие правки сохраняются в `localStorage` и имеют приоритет
над реестром, при этом кнопка «Вернуть значения реестра» откатывает их.

## ⚠️ Что стоит уточнить

* **Лицевые счета водоснабжения объектов № 1 (кв. 31) и № 6 (дом)** помечены «данные уточняются» —
  как и указано в исходных данных. Впишите номер через ⚙️ «Параметры услуги» → «Лицевой счёт
  ГУП РК "Вода Крыма"».
* **Приборы учёта воды** (номера, модели, даты госповерки) пока не заполнены: в разделе «Госповерка»
  они отображаются как «Нет данных». Заполните через ⚙️ — система сразу начнёт следить за сроком.
* **Даты индексации тарифа воды** в исходных данных не указаны, поэтому базовый график состоит из
  одной строки (актуальный тариф 47,96 ₽ на все периоды). Добавьте строки в селекторе периодов,
  когда появятся даты изменений, — прошлые начисления при этом не изменятся.
* Тарифы обновляются региональными постановлениями: после очередной индексации поправьте ставки
  в `config.js` (или в интерфейсе) — история прошлых месяцев сохраняется.
